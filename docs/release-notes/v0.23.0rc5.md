## Overview

v0.23.0rc5 is the fifth release candidate of v0.23.0: v0.23.0rc4 rebuilt on icpp-pro 7.0.0rc7, the candidate for icpp-pro 7.0.0. Its Candid decoder traps on invalid or abusive messages instead of reading out of bounds or hanging. Nothing else changes since rc4, except that a client that sends a vec of another element type than the `.did` declares now gets a trap.

### Highlights

- Hardened Candid decoder: spec-invalid or abusive messages trap instead of reading out of bounds or hanging ([#72](https://github.com/onicai/llama_cpp_canister/pull/72))

### Behaviour changes for apps

- A vec must have the element type the `.did` declares: e.g. a `vec text` where a `vec nat8` is expected now traps ([#72](https://github.com/onicai/llama_cpp_canister/pull/72))
- New limits per message: a nesting depth of 128, and 1,000,000 values that take no bytes on the wire ([#72](https://github.com/onicai/llama_cpp_canister/pull/72))

### Upgrade notes

- Upgrade every canister built from v0.23.0rc4 or earlier; an upgrade from rc4 keeps the uploaded models ([#72](https://github.com/onicai/llama_cpp_canister/pull/72))
- Some replies can be a few bytes smaller (an extra opt argument no longer adds its types): same values, different bytes ([#72](https://github.com/onicai/llama_cpp_canister/pull/72))

### icpp-pro

- icpp-pro [7.0.0rc7](https://github.com/icppWorld/icpp-pro/releases/tag/v7.0.0rc7), from 7.0.0rc4: the decoder hardening, faster decoding of wide records and vecs of variants ([#72](https://github.com/onicai/llama_cpp_canister/pull/72))
