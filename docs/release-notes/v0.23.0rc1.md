## Overview

v0.23.0rc1 is the first release candidate of v0.23.0, the self-call release: one update call can now return a whole answer, because the canister yields to itself between chunks. `run_update_full` generates a complete response, `run_decision_full` answers a whole decision request, and `run_update` stops before the instruction limit instead of trapping. It also keeps the last logits next to each prompt cache, makes the cap on stored Kev states per scope configurable, adds a log monitor, and moves to icpp-pro 7.0.0rc2.

### Highlights

- New `run_update_full`: ingests the prompt and generates the whole response in one update call, yielding to itself between chunks ([#54](https://github.com/onicai/llama_cpp_canister/pull/54))
- New `run_decision_full`: answers a whole decision request in one update call, for Julia-1 and Kev-0.8B ([#55](https://github.com/onicai/llama_cpp_canister/pull/55))
- `run_update` stops a chunk at a 36B instruction guard instead of trapping at the 40B limit, so a longer context cannot trap ([#53](https://github.com/onicai/llama_cpp_canister/pull/53))
- A continued session samples its first token from its own logits, saved in a `.logits` sidecar, never from another caller's ([#50](https://github.com/onicai/llama_cpp_canister/pull/50))
- Every README uses one `run_update_full` or `run_decision_full` call, with `max_tokens_update = 0` (no cap) ([#56](https://github.com/onicai/llama_cpp_canister/pull/56), [#60](https://github.com/onicai/llama_cpp_canister/pull/60))

### Behaviour changes for apps

- A `run_update` chunk can end before `max_tokens_update` tokens at the instruction guard; keep looping until the response ends ([#53](https://github.com/onicai/llama_cpp_canister/pull/53))
- `run_update_full` needs `--prompt-cache`, refuses `--model` (400), and sets `partial = true` when stopped or after 500 chunks ([#54](https://github.com/onicai/llama_cpp_canister/pull/54))
- A session (principal plus prompt cache) held by a `run_update_full` gets 409 from `run_update`, `new_chat` and `remove_prompt_cache` ([#54](https://github.com/onicai/llama_cpp_canister/pull/54))
- A held session expires after 10 minutes without progress; `copy_prompt_cache` and `upload_prompt_cache_chunk` to it return an error ([#54](https://github.com/onicai/llama_cpp_canister/pull/54))
- While a `run_update_full` or `run_decision_full` runs, `load_model` and `run_update --model` return 409 ([#54](https://github.com/onicai/llama_cpp_canister/pull/54), [#55](https://github.com/onicai/llama_cpp_canister/pull/55))
- Laya: `run_decision_full` takes one question per request; a step after a yield returns an Err that points to `run_decision` ([#55](https://github.com/onicai/llama_cpp_canister/pull/55), [#60](https://github.com/onicai/llama_cpp_canister/pull/60))
- `instructions` in a decision reply now counts every message of the call, for `run_decision` too ([#55](https://github.com/onicai/llama_cpp_canister/pull/55))
- At `max_tokens_update = 0`, a multi-question Julia-1 or Laya request no longer traps: first-message passes are guarded at 36B ([#58](https://github.com/onicai/llama_cpp_canister/pull/58))
- Laya's first question after `load_model` is not checked: a too-long one gets an IC0522 reject; set `max_tokens_update = 32` for an Err ([#58](https://github.com/onicai/llama_cpp_canister/pull/58), [#60](https://github.com/onicai/llama_cpp_canister/pull/60))

### Candid API changes

- New `run_update_full : (InputRecord) -> (OutputRecordResult)` and `run_decision_full : (DecisionInputRecord) -> (DecisionResult)` ([#54](https://github.com/onicai/llama_cpp_canister/pull/54), [#55](https://github.com/onicai/llama_cpp_canister/pull/55))
- `RunOutputRecord` gains `partial : opt bool`, set only by `run_update_full` ([#54](https://github.com/onicai/llama_cpp_canister/pull/54))
- `max_decision_states_per_scope : opt nat64` in the cache-cleanup config input, config record and stats record ([#59](https://github.com/onicai/llama_cpp_canister/pull/59))

### Upgrade notes

- Prompt caches written by an older build still load; without a `.logits` sidecar they continue as before and get one after their next call ([#50](https://github.com/onicai/llama_cpp_canister/pull/50))
- `max_decision_states_per_scope` (default 8, 0 = no limit) is saved in `.canister_settings.json` and survives upgrades ([#59](https://github.com/onicai/llama_cpp_canister/pull/59))

### Models and guides

- Kev-0.8B guide: a walkthrough with one `run_decision_full` call per request, "Ask one question at a time", and a new demo GIF ([#56](https://github.com/onicai/llama_cpp_canister/pull/56))
- Decision guides use `run_decision_full`, document its partial reply and the cap per scope; Laya sends one question per request ([#56](https://github.com/onicai/llama_cpp_canister/pull/56), [#59](https://github.com/onicai/llama_cpp_canister/pull/59), [#60](https://github.com/onicai/llama_cpp_canister/pull/60))
