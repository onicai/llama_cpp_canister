## Overview

v0.23.0 is the final release of the v0.23.0 series: v0.23.0rc5 rebuilt on icpp-pro 7.1.0, with changes to the release process and the release zip. A new IC replica refuses a wasm with more than 1100 exports, also on every call to an installed canister once it compiles the wasm again; earlier builds of this canister have thousands, and this one has 57. Upgrade every deployed canister. The features of the series are in the notes of v0.23.0rc1 to v0.23.0rc5.

### Highlights

- The wasm exports only its entry points and its memory: 57 exports, under the IC's new limit of 1100 ([#77](https://github.com/onicai/llama_cpp_canister/pull/77))

### Behaviour changes for apps

- Stricter decoding: trailing bytes, a bool other than 0 or 1, invalid UTF-8, bad or over-32-bit field ids trap ([#73](https://github.com/onicai/llama_cpp_canister/pull/73))
- The decoder's trap messages are new, and a principal over 29 bytes traps; update tests that match the old text ([#73](https://github.com/onicai/llama_cpp_canister/pull/73))
- Replies with a record, variant, opt or vec have new Candid bytes (same values); re-pin clients that hash them ([#73](https://github.com/onicai/llama_cpp_canister/pull/73))
- Arguments are positional: a missing one must be opt, null or reserved, extra ones are skipped, invalid argument types trap ([#73](https://github.com/onicai/llama_cpp_canister/pull/73))

### Upgrade notes

- Upgrade every canister, and stop it fully first: from this build on, an upgrade while it is still stopping traps ([#77](https://github.com/onicai/llama_cpp_canister/pull/77))
- Where the subnet already refuses the old wasm, upgrade with `skip_pre_upgrade`: see the icpp-pro 7.1.0 notes ([#77](https://github.com/onicai/llama_cpp_canister/pull/77))
- Files in stable memory stay: models, prompt caches, decision states; call `load_model` and `set_max_tokens` again
- Settings, admin roles and the cache-cleanup config stay too, saved in `.canister_settings.json` ([#46](https://github.com/onicai/llama_cpp_canister/pull/46))
- stable-fs 0.13.1 fixes a bug: after an upgrade, shrinking an old file to a multiple of 4096 bytes zeroed data ([#73](https://github.com/onicai/llama_cpp_canister/pull/73))
- That applies to files written with icpp-pro 7.0.0rc2 or earlier (v0.23.0rc1 and older); data already zeroed stays lost ([#73](https://github.com/onicai/llama_cpp_canister/pull/73))

### icpp-pro

- icpp-pro [7.1.0](https://icpp-pro.onicai.com/release-notes.html), from 7.0.0rc7 via 7.1.0rc2 ([#73](https://github.com/onicai/llama_cpp_canister/pull/73)); ic-wasi-polyfill v0.13.2 ([#77](https://github.com/onicai/llama_cpp_canister/pull/77))

### Scripts and tooling

- The README says the last ingest call can return no token; the first token then comes from a later call ([#75](https://github.com/onicai/llama_cpp_canister/pull/75))
- Every release goes through a release PR and a review PR with a security scan; `release.yml` builds the reviewed commit ([#74](https://github.com/onicai/llama_cpp_canister/pull/74))
- The release zip no longer ships `src/llama_cpp_onicai_fork/requirements*`; use the fork in `src/` of a clone, or a llama.cpp checkout ([#76](https://github.com/onicai/llama_cpp_canister/pull/76))
