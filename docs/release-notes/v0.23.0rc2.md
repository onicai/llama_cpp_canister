## Overview

v0.23.0rc2 is the second release candidate of v0.23.0. It moves to icpp-pro 7.0.0rc3 and its new stable-memory file system, with an upload fix that the new file system needs, and it adds sequence classifiers: `run_classify` and `run_classify_query`, loaded with upstream llama.cpp's `--embedding --pooling rank`, with a DAO moderation classifier as a worked example.

### Highlights

- New `run_classify` (update) and `run_classify_query` (query) for sequence classifiers such as BERT and ModernBERT ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- Example: a DAO-channel moderation classifier (Ettin-17M, f32, 15 scores per message), published as onicai/dao-moderation-classifier ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- New stable-memory file system (icpp-pro 7.0.0rc3): a model takes about its file size, and LFM2.5-2.6B now loads ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))

### Candid API changes

- New `run_classify : (ClassifyInputRecord) -> (ClassifyResult)` and the query `run_classify_query` with the same types ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- New records `ClassifyInputRecord { text }` and `ClassifyOutputRecord { scores; labels; input_tokens; instructions }` ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))

### Upgrade notes

- An upgrade keeps the models and stored decision states that the old file system wrote (verified with Kev-0.8B) ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))
- Plan stable memory at about a model's file size: the 1.67 GB LFM2.5-2.6B takes 1.74 GB, down from 2.81 GB before ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))
- A later upload chunk no longer truncates the file; without that fix, the new file system kept only the last chunk ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))
- A corrupt `uploaded_files_metadata.dat` no longer makes the metadata reader allocate without bound ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))

### Models and guides

- New `README-classifier-models.md`: load arguments, measurements, query vs update, limits; f32 is recommended over f16 ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- New `README-classifier-training.md` and `examples/classifier/`: the DAO moderation example step by step, up to the canister test ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- A classifier text is limited to 8192 bytes and the `-ub` tokens of the model's load; a longer one gets an Err ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- With a classifier loaded, `new_chat`, `run_update`, `run_query` and `run_update_full` return "use run_classify" ([#64](https://github.com/onicai/llama_cpp_canister/pull/64))
- LFM2.5-2.6B guide: the current Hugging Face file loads with this release and answers a `run_update_full` call ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))

### icpp-pro

- icpp-pro [7.0.0rc3](https://github.com/icppWorld/icpp-pro/releases/tag/v7.0.0rc3), with the stable-fs 0.13.0 file system (ic-wasi-polyfill v0.13.0) ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))

### Scripts and tooling

- `scripts/upload.py` and `scripts/download.py` stop with a clear error when the identity or the canister id cannot be found ([#63](https://github.com/onicai/llama_cpp_canister/pull/63))
- For contributors, `make test-llm-native` runs the native tests under a memory guard that stops a run above 4 GB ([#62](https://github.com/onicai/llama_cpp_canister/pull/62))
